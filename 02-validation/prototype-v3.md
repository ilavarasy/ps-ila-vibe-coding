## What it tests

_Tie it back to the validation brief: which assumption does this prototype put in front of a user?_

The data is all there, but users can't find the insight, so they bounce.

## Context injected (no placeholders)

- **Real user quotes on screen:** “I open it, see twelve charts, and have no idea which one I'm supposed to act on. So I close it.” / “The number I need is in there, but it takes six clicks and three filters to find it.”
- **Domain metrics on screen:** 60% Bounce rate: sessions under 15s with no interaction. / 12 Charts on the default landing view. / 6 clicks To reach the most-requested metric.

## Iteration log (v1 → v3)

| Version | Change | Why |
|---|---|---|
| v1 | Single page with single insight metrics | My assumption was that too many charts are confusing the users. They do not know what the insight is with all the data. |
| v2 | Design improvement to match the company design and also added a clickable action. | The insight was highlighted but the user would not know the evidence, so included clickable action for the user to expand and see how the insight was derived. |
| v3 | this included the hypothesis and the stats on how the page is performing. Shows the before and  after of the dashboard updates | it includes the success metrics and kill switch |
